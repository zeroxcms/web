// 01

內容模型

worker 27 kB · views 25 kB
  • 「Lect」結構化內容 — 每個頁面的主體都是一份具明確結構的 JSON：localized 欄位、scalar attribute（@）、page-reference pointer（*）、可重複的 items、可重用的 blocks（_blocks）及 tags（_tags）。_type、_modifier、_pointers 等 metadata 亦並列其中。
  • Blueprint 驅動的 schema — 頁面類型以 blueprint 宣告（欄位字串與巢狀 item map 的組合）；編輯器表單、搜尋路徑及 CSV header 全部由同一 blueprint 衍生。
  • 內建多語支援 — 預設語言集（mis、en、zh-hant、zh-hans），每個欄位都有 localized 值；語言按 request 選擇，並貫穿儲存／重載。
  • 18 種欄位類型，由 Liquid snippet 渲染：text、textarea、richtext、number、boolean、switch、checkbox、radio、select、date、time、color、email、tel、url、link、page（page-reference combobox）及 picture。
  • Page-reference 欄位 — 由 JSON API 支援的可搜尋 combobox，把一個頁面連結到另一個（按類型，以 name／slug 篩選）。
  • 頁面層級 — 頁面可設定 parent（page_id）形成樹狀結構；parent 選項可搜尋。
  • 排程視窗與時區 — 每個頁面帶可選的 start／end 時間戳及時區（UTC offset 或 IANA 名稱；預設可經 DEFAULT_TIMEZONE 設定）。
  • Weight 排序 — 每頁可手動設定排序 weight，支援即時編輯及批量端點。
  • 舊格式正規化 — 較舊的「structured」JSON 形態會在讀取時自動遷移到現行 lect 模型。
  • Lect 合併語意 — blueprint 預設 ← 已存內容 ← 傳入的部分內容，因此 API 呼叫方及匯入工具只需送出有改動的欄位。
✍️

// 02

頁面編輯器

worker 97 kB · views 47 kB
  • 結構化編輯器 UI — Tailwind ＋ vanilla-JS 的後台表單，會渲染每個 blueprint 欄位、item 列表及 block 列表，並附有 rich text 的內嵌 HTML 工具列。
  • 完整頁面 CRUD — 建立（空白或 create_by_type）、編輯、更新及軟刪除，並自動產生 slug 且保證唯一。
  • 編輯器內結構化動作 — 無需離開頁面即可新增／移除／重排 items 與 blocks（伺服器套用結構化動作後重新渲染）。
  • 伺服器端驗證 — 以 422 及錯誤清單重新渲染表單，同時保留已輸入的值。
  • 插件 edit view — 插件可接手它所擁有頁面類型的整個 edit/new 表單；CMS 把編輯器 context POST 給插件，並把回傳的 HTML fragment 包進後台 chrome。其表單會 POST 回正常的 CMS 儲存 handler，因此 versioning／發佈邏輯不變。
  • 優雅 fallback — 若插件 edit view 回傳 404 或任何錯誤，就改用內建編輯器，因此半成品插件永遠無法把編輯者鎖在頁面之外。
  • 內建編輯器 escape hatch — 在 URL 加上 ?native=1（或 ?editor=cms），即可對本應由插件渲染的頁面強制使用內建編輯器；此旗標在驗證錯誤及儲存後重載時仍會保留。
  • 保留返回路徑 — 編輯器會記住你的來源（例如某插件 dashboard），儲存後 Back／Cancel 仍指向該處。
  • 唯讀頁面檢視 — /pages/:id/read 把同一份結構化內容渲染成靜態文字（無輸入欄、無 CRDT、無在席狀態），可安心查閱頁面而絕無誤改風險；擁有該頁面類型的插件亦可渲染此檢視，同樣支援 ?native=1 fallback。
  • 私隱表格檢視 — 含 email／phone／mobile／fax 欄位的頁面類型，會以顧及私隱的方式渲染列表。
  • 修改者標示 — 解析並顯示最後編輯者的名字。

// 03

版本與歷史

worker 4 kB +shared
  • 每次儲存都有版本 — 每次 create/update 都會新增一筆 page_versions；draft_pages.current_page_version_id 指向使用中的版本。動作（create/update/publish/revert/restore）會被記錄。
  • 版本歷史面板 — 編輯器列出最近 20 個版本，附時間戳及動作。
  • 版本預覽 — 以唯讀方式打開任一歷史版本（?version=…），並與目前草稿比對差異。
  • 回復／還原 — 把頁面回退到任一先前版本；回復本身亦成為新版本（歷史只追加）。
  • Live 版本指示 — 編輯器標示目前哪個已存版本與已發佈內容相符。
  • 歷史隨回收筒保留 — 版本 row 與 tag link 會隨頁面移入回收筒，還原時完整回來（id 保留）。
  • 插件及 API 寫入亦有版本 — 每次回寫 API 的 create/update/delete 都會新增版本並觸發對應的 lifecycle hook，與後台編輯器完全一致。
  • 自訂版本動作 — API 更新可在歷史中記錄自己的動作標籤（例如插件的業務動作「已簽到」），而不只是籠統的 update。
  • 刪除版本 — 移除單一版本，或一次過清理頁面的全部歷史（皆需確認）；current-version 指標會重新指向最新剩餘的版本。
  • 認得時區的歷史 — 版本時間戳以設定的預設時區格式化，而非原始 UTC。
🛰️

// 04

即時協同編輯

worker 10 kB · views 14 kB
  • 每頁一個 Durable Object（PageSyncDO）透過 WebSocket 協調並行編輯者，令團隊不會默默覆蓋彼此的工作。
  • CRDT overlay 模型 — 一層 未提交 編輯的即時 overlay 疊在最後儲存的頁面之上。Op 以 (欄位, 使用者) 為單位儲存，因此可獨立丟棄某位編輯者的改動。
  • 以 HLC 決定 last-write-wins — 每個欄位的有效值，是跨使用者中 hybrid logical clock 最高的 op。
  • 未儲存即離開的還原 — 當編輯者未儲存就斷線，其未提交的改動會被丟棄，每個受影響欄位回退到下一位編輯者的值，或已儲存的 baseline。
  • 儲存即提交 overlay — 儲存會清掉未提交 op，並把已儲存的值推送為所有人的新 baseline（先儲存再離開絕不會回退）。
  • 欄位層級的在席標示 — 短暫的 focus/blur 訊號顯示每位協作者目前在哪個欄位（只作轉發，不儲存）。
  • 帶心跳的在席名單 — presence API 追蹤誰在頁面上（名字、頭像、last-seen／last-active），逾時項目 10 分鐘後自動過期。
  • 多分頁安全 — 只要使用者仍有任一連線（例如第二個分頁）開著，其 op 便會保留。

// 05

發佈

worker 19 kB
  • Adapter 式發佈目標 — 一次發佈會建立單一頁面 snapshot（row ＋反正規化的 tag link），並分發到每個已設定的目標；取消發佈及刪除會以同樣方式從所有目標移除。
  • 草稿 ↔ 已發佈分離 — 草稿存於私有 CMS 資料庫；發佈會寫入一個 獨立的已發佈資料庫，可只把它給公開讀取的 Worker（無法存取 users、sessions、drafts 或 trash）。
  • 內建 d1 目標 — 以 uuid upsert live_pages／live_page_tags；取消發佈會刪除兩者。
  • 內建 r2 目標 — 寫出靜態 JSON：pages/<uuid>.json（完整 snapshot，lect 已解析）加上一份滾動的 index.json，列出所有 live 頁面。
  • 插件發佈目標 — 任何 manifest 宣告 publishTarget: true 的插件，會透過三個 POST 端點自動收到 publish/unpublish/tag-removal snapshot（IPFS pin、webhook、搜尋索引、靜態重建）。
  • await 分發並回報部分失敗 — 發佈目標會被 await；個別目標失敗會被記錄並在編輯器 flash 顯示（「已發佈，但這些目標失敗：…」），而不阻塞成功的目標。
  • 發佈狀態徽章 — dashboard 從第一個可讀的目標讀取 live 狀態，逐頁顯示 draft/live。
  • 把已發佈頁面拉回草稿 — 將 live 頁面拉回草稿以供編輯（若無草稿則建立）。
  • 取消發佈及儲存時發佈 — 可直接在 dashboard 發佈，或在儲存時以 publish 動作發佈。
🏷️

// 06

分類與標籤

worker 19 kB · views 15 kB
  • Taxonomies（分類） — 具名的分組（years、categories、topics、collections…），在其專屬後台管理（受 taxonomy:write 控制）。
  • Tags（標籤） — 分類之下的詞項，帶 localized 名稱、slug 及可選的 parent-tag 巢狀（受 tag:write 控制）。
  • 頁面↔標籤多對多連結 — tag 掛到草稿頁面上，並隨其貫穿發佈、回收筒及還原。
  • 內嵌 tag 指派 API — 透過 JSON 端點新增／移除頁面的 tag（並更新頁面的 updated_at）。
  • Tag 挑選器 — 出現在編輯器及進階搜尋中，按分類分組。
  • Tag weight 與批量重排 — 每個 tag 可手動設定排序 weight，並有批量重排端點，一次呼叫即可為整個分類重新排序。
  • 以 slug 為 key 的分類 — tag 以 slug 引用其分類（改名安全）；插件定義的分類會與內建分類一同出現在 tag 後台。

媒體

worker 7 kB
  • 私有 R2 上載 — picture 欄位上載到私有 R2 bucket（永不公開）；Worker 在 /media/<key> 對每次讀取設閘，需有效 session。

  • 即時縮圖 — /media-preview/<key> 提供經 Cloudflare Image Resizing 最佳化的預覽（100×100 cover），若未啟用 transformation 則回退到原圖。
  • 限速並需權限 — 上載需 media:upload，並按 IP 限速。

回收筒與還原

worker 13 kB · views 8 kB
  • 軟刪除 — 刪除頁面會把它（連同版本歷史及 tag link）複製到回收筒，並保留 id，令日後還原保持同一身分，同時從每個目標取消發佈。
  • 回收筒瀏覽器 — 分頁列表，附逐類型篩選下拉、完整類型計數細分，及「過去一小時內丟棄」計數。

  • 永久刪除／清空回收筒 — 清除單一 row，或清空全部／按類型／只限過去一小時（受 trash:purge 控制）。
  • 可稽核 — 還原與清除動作會寫入 audit log。

// 12

驗證與身分

worker 45 kB · views 4 kB
  • OAuth 2.1 + PKCE 登入（S256 code challenge），支援五個 provider：GitHub、Google、Microsoft/Entra、Apple 及自架的 Eventuai。登入頁會按 ENABLED_PROVIDERS 的次序，每個 provider 顯示一個按鈕。
  • Provider 抽象層 處理各 provider 的差異：Microsoft tenant 選擇（common／organizations／consumers／tenant id）、Apple form_post response mode，以及 ID-token 對 userinfo endpoint 兩種取得身分的方式。
  • ID-token 驗證（Apple）：在信任 claims 前，先核對 issuer、audience（client id）及 expiry。
  • 無狀態 PKCE 流程 — state ＋ code verifier ＋所選 provider 都放在已簽署、10 分鐘有效的 oauth_state JWT cookie（加 __Host- 前綴，secure origin 上為 SameSite=None），登入期間毋須任何伺服器端 session store。
  • 雙 JWT session：短命的 15 分鐘 access token ＋可輪換的 7 日 refresh token，兩者皆以 Web Crypto API 作 HS256 簽署，並以 httpOnly cookie 儲存。
  • Refresh token 可撤銷 — refresh JTI 經 SHA-256 hash 後存於 sessions 表；登出及輪換時會刪除，因此可在伺服器端使 token 失效。
  • 靜默 token 更新 — 透過 POST /auth/refresh（JSON）作 refresh token 輪換；後台頁面以 keepalive 維持 session。
  • Session 衛生 — 每位使用者的並行 session 有上限，過期的 session row 會伺機清理（經 waitUntil，不阻塞回應）。
  • 多 provider 帳戶連結 — 可在個人檔案頁或 /auth/start?provider=…&link=1 把額外 provider 連結到同一 CMS 帳戶；系統不會僅因電郵相同就默默合併已登出的帳戶。
  • 身分表（user_oauth_identities）將多個 provider 身分對應到同一使用者，並為未 backfill 的資料庫保留 oauth_id legacy fallback。
  • 可選的註冊白名單 — ALLOWED_EMAIL_DOMAINS 限制誰可建立新帳戶；已連結的現有使用者永遠通過，設定改動不會把任何人鎖在門外。
  • 首次登入時配置角色 — IdP 提供的角色只在首次建立帳戶時套用；之後登入會更新 profile 欄位，但絕不覆寫 CMS 角色，因此後台的角色改動會保留。
  • 憑證端點限速 — /auth/start、/auth/callback 及 /auth/refresh 均按 IP 限速。
  • 弱密鑰保護 — 若 JWT_SECRET 缺失或少於 32 字元，Worker（在 localhost 以外）會拒絕服務，令人無法偽造後台 token。

存取控制與權限

worker 28 kB · views 14 kB
  • 以能力為本的授權 — 路由要求特定 權限（例如 content:publish），而不只是「是不是 editor」。使用者的有效權限，是其持有所有角色的聯集（角色以逗號分隔）。

插件系統

worker 82 kB · views 19 kB

每個插件都是獨立的 Cloudflare Worker，透過 HTTPS 在 {url}/__plugin/… 觸達。CMS 會發現插件、快取其 manifest，並在每次呼叫時轉發已登入使用者及一個共用 secret。插件可加入八類擴充：

  • Lifecycle hook — 在頁面 create / update / publish / unpublish / delete 時執行（webhook、外部索引、快取清除、通知）。Hook 屬盡力而為，絕不阻塞編輯器。
  • 內容類型 — 註冊新的 blueprint／blocks／block-list／taxonomy-list，合併進編輯器設定。
  • 欄位與區塊 — 註冊新的 pagefield 類型並提供其 Liquid snippet，透過 CMS 編輯器渲染。
  • Edit view — 為所擁有的頁面類型渲染整個 edit/new 表單（見 §02）。
  • 後台路由 ＋ nav — 加入一個代理於 /admin/plugins/<id>/… 的後台頁面及一個 nav 項目；nav 項目可置於 Settings 群組之下，並按角色限制顯示。
  • 發佈目標 — 宣告 publishTarget: true 即可收到發佈 snapshot（見 §05）。
  • 配額限制 — 宣告可由管理員設定的上限，限制某類型頁面的數量（見 §16）。
  • Credit 收費 — 宣告可收費的動作，從使用者的 credit 餘額扣賬（見 §16）。

// registry 與安全

  • 執行時註冊（毋須重新部署） — 在管理後台以 URL 註冊／啟用／停用／設定插件（受 plugin:manage 控制），存於 plugins 表。Manifest 會自動發現並快取。
  • 逐插件 secret — 每個插件都有自己產生的共用 secret（回退到 env PLUGIN_SECRET），因此可獨立輪換或撤銷某個插件而不影響其他。
  • 後台代理 — 插件後台頁面代理於 CMS origin 之下，包進後台 chrome，並套用嚴格 nonce CSP（受 plugin:access 控制）。完整文件的插件回應可選擇以 same-origin iframe 顯示。
  • SSRF 防護 — 若插件 URL 解析到明顯的 private／loopback／link-local（含 cloud metadata 169.254.169.254）／CGNAT／.internal 字面位址，會被拒絕。
  • 已核准的靜態資產 — 插件可提供在 CMS chrome 內執行的 JS/CSS（例如 camera scanner），但管理員必須明確核准每個路徑，並釘住其 SRI（sha384）內容 hash，才能通過消毒。
  • 委派的頁面類型存取 — 配套插件可為它並不擁有的頁面類型申請 readTypes／writeTypes；管理員須核准每個委派範圍，CMS 方會遵從。範圍可以是 wildcard *，獲核准後即涵蓋所有頁面類型。
  • 帶版本的插件 view 檔 — 插件 view／資產檔以 immutable、以 revision 為 key 的快取提供。
  • 未用時零負擔 — 未設定任何插件時，系統不增加任何開銷。

插件回寫 API /__cms

worker 55 kB

一條反向的 server-to-server 通道（以逐插件 secret 驗證，位於瀏覽器驗證堆疊之外），令插件自家網域上面向訪客的流程 — 公開 RSVP 提交、QR 簽到、批量聯絡人匯入 — 可讀寫它所擁有或獲委派的 CMS 頁面。

  • 受範圍限制的讀寫 — 呼叫方以 x-plugin-id 表明身分；寫入僅限其 manifest 頁面類型加管理員核准的 writeTypes，讀取亦可觸及已核准的 readTypes。
  • 列出／讀取頁面 — 按類型分頁列出，支援 name/slug/lect 搜尋（含中文變體）、parent 篩選及 lect-pointer 篩選（單值或多值 IN）。
  • 支援大型 lookup 的讀取 — 直接 ids/slugs lookup 及 include_tags=1 list 使用 JSON-array binds，支援最多 500 個值而不超出 D1 的 100-parameter limit。
  • 進階搜尋端點 — POST /pages/search 接受與後台進階搜尋相同的多條件語意（AND/OR/NOT 運算子、blueprint 欄位路徑、tag 篩選、中文變體），限於呼叫方可讀的類型，每頁最多 500 筆。
  • 建立與批量建立 — 單筆及最多 100 頁的批量建立共用同一流程，處理 validation、ID/parent resolution、quotas、credits、DB writes 及 hooks；批量保留 all-or-nothing 的 limits/credits 語意，並回報逐項 errors。
  • 部分更新 — PUT/PATCH 只合併送出的欄位（blueprint ← 已存 ← 傳入），重新產生版本，並提交 live overlay；更新可為其產生的版本標上自訂動作字串。
  • 批量發佈 — POST /pages/publish 透過標準 target pipeline 發佈最多 100 個 draft page ID，強制呼叫方的 page-type scope、拒絕無效或重複 ID、逐項回報 target failure，並觸發 publish hooks。
  • 認得 credit 與配額 — 有定價的頁面類型會在寫入前扣賬（餘額不足回傳 402 並附成本細項；寫入失敗會自動退款），配額限制亦在每次建立（單筆或批量）時強制執行（見 §16）。
  • 伺服器端批量複製 — 以 lect pointer 或 parent id 複製一組相關集合（例如某活動的賓客），套用統一的 lect 轉換（丟棄 key、合併覆寫），以有界 chunk 處理並回傳續傳 cursor，令任意大的清單可分多個 request 完成複製。
  • 伺服器端批量刪除 — 軟刪除一組相關集合（按 pointer 或 parent），以及按 id 清單批量刪除，兩者皆分 chunk 且可以 cursor 續傳。
  • 帶版本、可稽核、可觀察 — 每次 create/update/delete 都會新增頁面版本、寫入歸屬於 plugin:<id> 的 audit row，並向其他插件觸發 lifecycle hook。
  • 留意 subrequest 額度 — batch 大小及每次呼叫上限，皆調校至留在 Workers 免費方案的 subrequest 限制之內。

Credit 與配額限制

worker 26 kB · views 7 kB

為插件讓使用者做的事計量或收費。插件的 manifest 負責宣告可收費動作與配額限制，管理員負責設定價格與上限，host 則在每條頁面建立路徑上強制執行 — 後台編輯器與回寫 API 一視同仁，任何一道門都無法用來繞過另一道。

  • 每使用者餘額與只追加的賬本 — 每位使用者都有 credit 餘額；每次變動都會追加一筆 credit_ledger（delta、變動後餘額、動作、實體、插件、備註、執行者），賬本永遠能解釋餘額。
  • Manifest 宣告的收費 — page_create 收費由 host 在該類型頁面每次建立時自動扣賬；metered 收費由插件經 POST /__cms/credits/charge 回報，用於 host 觀察不到的動作（例如發送 EDM）。
  • 管理員設定價格 — Plugins → Credits 畫面為每項宣告的收費定價（0 ＝ 明確免費）；未設定的收費回退到 manifest 預設。若多個插件為同一頁面類型定價，有效成本是總和。
  • 結構上不可透支 — 賬本 INSERT 與餘額 UPDATE 共用 credits ≥ amount 防護，在同一個 D1 batch（交易）內執行，並行消費永遠不會令餘額變負數；成功與否以 RETURNING 驗證。
  • 402 附成本細項、自動退款 — 餘額不足會拒絕建立並逐項列出定價部分；若已扣賬的操作在下游失敗，會盡力退款並記錄為獨立賬本項。
  • 管理員增減 — users:manage 可調整任何餘額，備註必填並寫入 audit log；個人檔案頁顯示分頁賬本，側欄顯示你的即時餘額。
  • 可設定的配額限制 — 插件宣告某類型頁面數量的上限，範圍可以是 total、per-parent 或 per-pointer（例如每個活動的賓客數）；管理員設定數值，或明確標記為無上限。
  • 批量安全的強制執行 — 會超過配額的批量建立或匯入會被整批拒絕，絕不半途套用；違規會回傳指向該限制、人類可讀的訊息。
  • 受範圍限制的宣告 — 插件只能為其擁有或獲委派（已核准）的頁面類型定價或設限；宣告會被驗證、去重，每插件上限 20 項，惡意 manifest 無法封鎖或向其他插件的內容收費。

安全加固

worker 9 kB +shared
  • 嚴格 CSP 加每 request nonce — default-src 'self'、以 nonce 控制的 script、base-uri 'none'、object-src 'none'、frame-ancestors 'none'；個別路由可選擇啟用 wasm-unsafe-eval（例如 zxing camera scanner）或 same-origin framing。
  • 每個回應都有安全 header — HSTS（preload，1 年）、X-Content-Type-Options: nosniff、Referrer-Policy: same-origin，以及預設的 X-Frame-Options: DENY。
  • fail-closed 跨來源修改防護 — 非安全方法會被拒絕，除非有瀏覽器訊號（Origin、Referer 或 Sec-Fetch-Site: same-origin）正面證明是 same-origin；無 header 的用戶端必須送出相符的 Origin。以 secret 驗證的 /__cms 通道則刻意豁免。
  • Canonical host 強制 — 對非 canonical host 的 request，GET/HEAD 回 308 導向、修改請求回 404，防止 host 混淆。
  • 鎖緊的 Permissions-Policy — camera／microphone／geolocation 預設拒絕；逐路由選擇性啟用。
  • 敏感路徑 no-store — /admin 及 /auth 回應設 Cache-Control: no-store。
  • 單次使用的 admin submit token — 已簽署的逐 form _cms_once token 會在 D1 作原子 claim 以阻止重複 POST；下游失敗時會釋放 claim，讓正常 retry 仍可完成。
  • 插件 fragment 消毒 — 代理的插件 HTML 在嚴格 nonce CSP 下執行並被消毒；除非以已核准、hash 釘住的資產提供，否則內嵌 script 一律移除。
  • 逐 IP 限速 — 在驗證及上載端點（Workers Rate Limiting binding）。
  • Audit log — 敏感動作（匯入、媒體上載、還原、清除、插件寫入）都記錄誰對哪個實體做了甚麼。
  • 預設私有的資料分離 — 公開讀取方可只獲得已發佈資料庫，完全無法存取 auth、sessions、drafts 或 trash。

資料與基礎架構

worker 46 kB
  • 100% 邊緣原生 — 單一 Cloudflare Worker（Hono router），沒有 origin server，也沒有需要看守的資料庫。
  • 兩個 D1 資料庫 — 一個私有 CMS store（auth、sessions、drafts、trash、taxonomy、versions、媒體 metadata、roles、plugins、jobs、approvals、settings、credit 賬本），及一個獨立的已發佈 store（live_pages／live_page_tags）。
  • R2 物件儲存 — 一個私有媒體 bucket，加一個可選的靜態 JSON 發佈 bucket。
  • Durable Objects — 逐頁 WebSocket 協調器，以 SQLite 儲存 CRDT op 及在席狀態。
  • Cloudflare Queues — CMS 自有 queue，用於耐久的背景後台工作。
  • 帶版本的 migration — 兩個資料庫皆有納入版控的 SQL migration（auth identity、admin job、plugin asset approval、plugin page-type approval、settings、tag weight 與 taxonomy slug、credits），並附本機一鍵 migrate script。
  • 認得部署 revision — view 資產以 Worker version metadata（或手動 fallback）作 cache-bust，新部署即令已快取的 CSS/JS 失效。
  • 全程 Web Crypto — JWT 簽署／驗證及 token hash 皆用平台 crypto API，無 Node 相依。

worker 8 kB
